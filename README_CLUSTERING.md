# Анализ и кластеризация сценариев утечек

Исследовательский вопрос: **какие группы похожих публично описанных инцидентов можно выделить и какие направления защиты соответствуют их характеристикам?** Это обучение без учителя. Целевую переменную и прогнозирование мы не используем.

## Начало работы в RStudio

Установите рабочую папку в каталог распакованного проекта. Данные уже подготовлены, интернет не нужен:

**Единый запуск с автоматическим показом результата:** откройте `OpenBaseSearch.Rproj` в RStudio и выполните:

```r
source("run_project.R", encoding = "UTF-8")
```

После анализа и кластеризации автоматически откроется браузер с `report.html`: размеры групп, таблицы механизмов, графики и ограничения. Файл остаётся в папке проекта; его можно открыть повторно без расчётов. При переносе HTML сохраняйте рядом папки `results_clusters/` с изображениями и таблицами. Автоматически запускать вычисления при одном лишь открытии `.Rproj` не требуется — запуск явный, одной командой.

Из терминала в папке проекта: `Rscript run_project.R`. Без открытия браузера: `Rscript run_project.R --no-open`. В RStudio отключить открытие можно через `options(openbasesearch.open_report = FALSE)`.

Для отдельного запуска этапов:

```r
source("analysis_vcdb.R")  # Описательная статистика
source("cluster_vcdb.R")  # Кластеризация и проверка устойчивости
```

Нужен R и пакет `cluster`, обычно поставляемый вместе с R. Если его нет, установите в R командой `install.packages("cluster")`. Python 3.10+ без дополнительных библиотек нужен для повторной подготовки признаков и запуска опыта с целостностью журнала. Если Python отсутствует, общий запуск использует сохранённые результаты опыта. Повторная подготовка признаков:

```sh
python3 prepare_clusters.py
python3 -m unittest -v
```

## Очистка и единица анализа

Исходные 10 047 карточек VCDB сохранены в `data_vcdb/`. Описательная основная выборка — 6911 карточек с подтверждённым инцидентом и раскрытием, без коллизий исходного ID и статуса Ineligible. Это карточки источника; уникальность реальных событий не гарантируется.

Для кластеризации используются **5347 карточек**, у которых есть хотя бы одно содержательное значение в каждом из четырёх семейств:

1. Действия: категории, разновидности и векторы.
2. Тип участника: internal, external, partner.
3. Виды затронутых активов.
4. Виды раскрытых данных.

**253 бинарных признака**, без null/NaN. Значение 1 означает зарегистрированную категорию; 0 — категория не записана, а не доказанно отсутствует. Пустое, Unknown, NA и типы вроде `S - Unknown` не создают фиктивные категории сходства. Карточки без полного покрытия семейств остаются в metadata с причинами исключения и в исходной базе. Они не получают выдуманный номер кластера.

Числовые поля не заполняются медианой. Масштаб утечки, отрасль, страна, год, названия организаций и ссылки **не участвуют в расстоянии**; они нужны для интерпретации и аудита. Размер утечки не является условием включения.

Полнота создаёт смещение отбора. Из 1564 исключённых из кластеризации карточек 788 относятся к сектору 92, а в полном ядре к нему относятся 897 из 5347. Сравнения включённых/исключённых по отрасли, году и действиям сохранены отдельно. Нельзя переносить полученные доли на все мировые утечки.

## Метод

Внутри каждого семейства считается расстояние Жаккара между наборами зарегистрированных категорий. Совместные нули не делают случаи похожими. Итоговое расстояние — среднее четырёх расстояний: каждое семейство имеет вес 25%, независимо от количества бинарных столбцов. Редкие содержательные категории сохранены, не склеены в искусственный Other.

Используется PAM — кластеризация вокруг реальных представителей групп, медоидов. Для снижения стоимости расчётов алгоритм обучается на трёх воспроизводимых подвыборках по 1000 карточек; остальные полные карточки назначаются ближайшему медоиду. Это приближённая кластеризация всего набора, а не полный PAM на всех парах 5347 карточек.

Для каждого k от 2 до 8 сравниваются три подвыборки. Общий оценочный набор из 600 карточек не входит ни в одну обучающую подвыборку. На нём измеряются silhouette и согласованность назначений ARI между запусками. Это исследовательский выбор k по оценочным данным, **не независимая оценка точности предсказаний**.

Выбирается максимальный средний silhouette среди k со средним ARI ≥ 0.7 и минимальной долей каждой группы ≥ 2% в оценочном наборе. Пороги эвристические; при отсутствии подходящего варианта скрипт явно сообщает о запасном выборе. Проверяется чувствительность к упрощению действий и исключению семейства участников.

## Результат текущего снимка

Основной вариант — **2 группы**: средний silhouette **0.339**, средний ARI между выборками **0.868**. Разделение умеренное; устойчивость не означает доказанную причинную модель. Вариант k=3 тоже устойчив (ARI 0.954), но слабее разделён (silhouette 0.280). Все сравнения доступны в `k_selection.csv`.

**Существенная зависимость от выбора признаков:** при упрощении действий до категорий ARI равен 0.947, но при исключении типа участника — лишь 0.178. Значит, эти две группы сильно зависят от включения actor. Их можно использовать как описательное деление внутренних и внешних сценариев, но нельзя называть универсальной или независимо обнаруженной типологией. Для исследования более узких механизмов внутри каждого сценария нужен отдельный эксперимент.

| Группа | Карточек | Основные зарегистрированные характеристики |
|---|---:|---|
| 1: преимущественно внутренние сценарии | 2478 | internal 93.9%; error 53.8%; misuse 44.3% |
| 2: преимущественно внешние сценарии | 2869 | external 98.5%; hacking 76.3%; malware 40.9% |

Категории пересекаются, доли не обязаны давать 100%. Названия групп — интерпретация профилей, а не метки, которые передавались алгоритму. При этом actor и action участвовали в расстоянии: получение похожего разделения ожидаемо и не является открытием ранее неизвестных причин.

Среди карточек с известным размером медианы составили 703 записи в группе 1 (1477 известных значений) и 9000 в группе 2 (1076). Это описательное сравнение неполных наблюдений, а не доказательство того, что внешняя атака причинно увеличивает ущерб. Записи не равны уникальным людям.

## Меры для обсуждения и проверки

- Для внутренних сценариев: минимальные права, разделение обязанностей, проверка получателей при отправке данных, контроль выгрузок и работа с документами. На учебном стенде можно измерить, какая доля ошибочных отправок блокируется и сколько возникает ложных блокировок.
- Для внешних сценариев: управление уязвимостями веб-приложений, защита учётных записей, мониторинг конечных устройств и ограничение перемещения между системами. На стенде можно сравнить обнаружение и сдерживание безопасных имитаций атак до и после меры.

Кластеризация помогает выбрать направления проверки, но **не измеряет эффективность защиты**. Детали механизмов следует сверять с источниками конкретных карточек. Не всем внешним сценариям подходят одни и те же меры.

## Файлы

В `data_clusters/`: `matrix.csv` (ID + бинарные признаки), `feature_dictionary.csv` (расшифровка), `metadata.csv` (исходные описательные поля и флаги отбора), `coverage.csv`, `manifest.json`. В metadata пропуски намеренно сохранены: это справочная таблица, не входная матрица модели.

В `results_clusters/`:

- `assignments.csv`: cluster, расстояние до медоида и разница расстояний между ближайшими медоидами. Маленькая разница означает неоднозначное назначение, а не вероятность.
- `cluster_summary.csv`, `feature_profiles.csv`, `top_features.csv`: размеры групп, представители, распространённость и отличие признаков от общей выборки.
- `k_selection.csv`, `all_runs.csv`, `sensitivity.csv`: выбор числа групп и устойчивость.
- `selection_*.csv`: влияние отбора полных карточек.
- Три PNG-графика, `report_ru.txt`, `model.rds` и `run_details.txt`.
- ID оценочной и выбранной обучающей подвыборки для воспроизводимости.

Для графиков и отчёта указывайте источник: **VERIS Community Database, vz-risk and contributors**, https://github.com/vz-risk/VCDB , **CC BY-SA 4.0**.
