# open-base-search

**Анализ и кластеризация инцидентов утечки данных для оценки применимости блокчейн-технологий в защите информации.**

Групповой учебный проект по дисциплине «Блокчейн». Python используется для подготовки данных и эксперимента с журналом, R — для анализа и кластеризации, HTML — для представления результатов.

**Выполнили:** Айдар Н., Бычков Н., Карим Д.  
**Группа:** СИБ-23-5

## Какую проблему решаем

Публичные сообщения об утечках неоднородны: в них различаются описания действий, участников, затронутых систем и полнота данных. Поэтому по отдельным сообщениям трудно выделить повторяющиеся сценарии и обоснованно выбрать меры защиты. Дополнительно требуется понять, какие задачи действительно может решать блокчейн и где достаточно обычной базы данных и проверяемого журнала.

Проект объединяет структурированные сведения об инцидентах, анализирует качество данных, выделяет группы похожих событий и сопоставляет задачи защиты с возможностями разных архитектур.

## Цель и задачи

**Цель:** выявить характерные сочетания признаков публично описанных утечек и оценить условия применения блокчейна для проверки целостности истории действий.

1. Подготовить воспроизводимый снимок открытых данных VCDB.
2. Проверить пропуски, статусы качества и коллизии идентификаторов.
3. Выделить группы похожих инцидентов и проверить устойчивость результата.
4. Сравнить базу данных, проверяемый журнал, цифровую подпись и блокчейн с ограниченным кругом участников.
5. Продемонстрировать обнаружение изменений журнала на синтетических событиях.
6. Автоматически сформировать визуальный отчёт.

## Данные и метод

Источник — [VERIS Community Database](https://github.com/vz-risk/VCDB), снимок commit `f6f98c00f66ab35f5b49977a5852ce94a5bb31d1`.

| Этап | Количество карточек |
|---|---:|
| Исходный снимок | 10 047 |
| Подтверждённые раскрытия после фильтров качества и коллизий ID | 6 911 |
| Карточки с необходимыми признаками для кластеризации | 5 347 |

Одна карточка описывает инцидент. Используются категории действий, типы участников, виды активов и данных. Личные записи пострадавших и пароли не собираются.

Кластеризация выполняется методом **PAM** с расстоянием Жаккара и равным весом четырёх семейств признаков. Сравниваются 2–8 кластеров, несколько обучающих выборок и общая отдельная оценочная выборка. Целевой переменной нет: проект выполняет анализ без учителя.

## Полученные результаты

- Выбраны **2 кластера**: 2 478 и 2 869 карточек.
- В первой группе преобладают внутренние ошибки и злоупотребления, во второй — внешние атаки.
- Средний silhouette: **0,339** — умеренное разделение групп.
- Средний ARI между запусками: **0,868** — согласованность разбиений, а не точность предсказания.
- Исключение признаков участника снижает ARI до **0,178**: результат существенно зависит от выбранного представления данных.

VCDB не является случайной выборкой всех утечек. Отбор заполненных карточек также вносит смещение. Частоты не измеряют вероятность взлома, а признаки инцидентов не доказывают причинно-следственные связи.

## При чём здесь блокчейн

Сравнение рассматривает, когда нескольким независимым организациям нужна общая проверяемая история. Для одного оператора база данных с защищённым журналом обычно проще. Блокчейн может быть обоснован при распределённом доверии, но сам по себе не предотвращает раскрытие данных.

`integrity_demo.py` реализует **хеш-цепочку**, проверяет подмену записи, полный пересчёт цепочки и удаление последней записи. Полный пересчёт проходит внутреннюю проверку, но обнаруживается сравнением с ранее сохранённой контрольной отметкой.

Контрольная отметка хранится локально только для демонстрации: её независимое доверенное хранение моделируется. Если злоумышленник заменит и журнал, и отметку, такая проверка не обеспечит защиту. **Полноценная блокчейн-сеть, консенсус и смарт-контракт в проекте не реализованы.**

## Быстрый запуск

Нужны R с пакетом `cluster`, RStudio для удобного запуска и Python 3.10+ для повторения эксперимента. Сторонние Python-библиотеки для основного запуска не нужны. Подготовленные CSV включены в репозиторий; повторное скачивание данных не требуется.

### 1. Получить проект — в терминале

```bash
git clone https://github.com/fortitude-devops/open-base-search.git
cd open-base-search
```

### 2. Запустить через RStudio

Откройте `OpenBaseSearch.Rproj`. Введите следующие команды во вкладке **Console** RStudio (строка с `>`):

```r
if (!requireNamespace("cluster", quietly = TRUE)) {
  install.packages("cluster", repos = "https://cloud.r-project.org")
}
source("run_project.R", encoding = "UTF-8")
```

### Альтернатива: запуск в терминале

Из папки проекта, после установки пакета `cluster`:

```bash
Rscript run_project.R
```

Команда `source(...)` предназначена для R, её нельзя вводить в командную строку zsh/bash.

После четырёх этапов откроется `report.html` с графиками и выводами. Если браузер не открылся, откройте файл вручную. Для запуска без открытия браузера используйте `Rscript run_project.R --no-open`. Если Python не найден, анализ выполняется с сохранёнными результатами эксперимента, о чём выводится сообщение.

## Структура проекта

| Путь | Назначение |
|---|---|
| `collect_vcdb.py` | Загрузка и преобразование VCDB |
| `prepare_clusters.py` | Подготовка признаков и выборки |
| `analysis_vcdb.R`, `vcdb_report.R` | Описательный анализ и текстовые выводы |
| `cluster_vcdb.R` | Кластеризация и проверки устойчивости |
| `integrity_demo.py` | Учебный эксперимент с целостностью журнала |
| `run_project.R`, `render_report.R` | Полный запуск и HTML-отчёт |
| `data_vcdb/`, `data_clusters/` | Исходные структурированные данные и признаки |
| `results_vcdb/`, `results_clusters/`, `results_integrity/` | Таблицы, графики и результаты опыта |
| `project_materials/` | Сравнение архитектур, сценарии и источники |
| `deliverables/` | Письменный отчёт и презентация |
| `DEFENSE_GUIDE.md` | Материалы для подготовки к защите |

Дополнительный сборщик `collect.py` и `analysis.R` работают с каталогом HIBP отдельно от основного исследования. Их данные не объединяются с VCDB.

## Проверка и воспроизводимость

В терминале из папки проекта:

```bash
python3 -m unittest test_collect test_vcdb test_clusters test_integrity_demo -v
```

Повторное получение данных и подготовка признаков (не требуется для обычного запуска):

```bash
python3 collect_vcdb.py
python3 prepare_clusters.py
Rscript run_project.R
```

Сборщик заменяет текущий снимок. Версия источника и преобразования записаны в `data_vcdb/manifest.json`. Пересборка DOCX через `project_materials/build_report.py` дополнительно требует `python-docx`; готовый документ уже включён.
